## 2026-10-12

- [Feat]: `scripts/seo-check/` (`npm run seo:crawl`), a zero-dependency crawler for the WordPress "before" site. It builds the 130-URL inventory from the committed WXR plus the live REST API for the author, checks every group count against PLAN.md §8 (a missing post fails with a per-group table), then fetches one URL at a time with manual redirects and records status, every hop, final URL, content type, title, meta description, canonical, robots, `X-Robots-Tag` and H1s by regex into `docs/before/old-urls.json` and `docs/before/seo-snapshot.json`. Raw responses go to `.cache/seo-check/before/` (now gitignored, with `docs/*/lighthouse/inbox/`), so `--from-cache` rebuilds with no network; two live runs and the cache rebuild were byte-identical apart from `crawledAt`. The login is read at runtime from `/wp-json/wp/v2/users`, scrubbed at capture (`/author/<author>/`, `larchwick-team`), and a leak guard refuses to write if any trace remains. Result: all 130 URLs end in 200, 52 via exactly one 301. No site code changed, 0 kB shipped.

- [Feat]: `scripts/lighthouse-import/import.ts` (`npm run lighthouse:import`, `-- --side after` for the rebuild). It takes Artem's manual "Save as JSON" reports from `docs/<side>/lighthouse/inbox/`, checks name, device and URL, strips every `data:image/…` value and `fullPageScreenshot` (keeping only its width and height), scrubs the login with the `Scrubber` it imports from `scripts/seo-check/privacy.ts`, and files each run as `<page>/<device>/run-N.json.gz`, then rebuilds `metrics.json` and `summary.md`. The median run is by Performance score, ties go to the lower LCP and an even count takes the lower middle. One rejected file means nothing is imported. On the two 2026-10-07 home reports, run in scratch: 795,607 B raw to 46,594 B gzipped, with all 2,140 numbers unchanged.

- [Chore]: rejected the `lighthouse` npm package, `chrome-launcher`, `@puppeteer/browsers`, jsdom and CDP screenshots. Artem measures by hand in Brave, the only browser installed, so a scripted Chrome would measure a different browser from his runs and add dependencies for nothing; WordPress's own head markup is regular enough for regex, so jsdom wasn't needed. Every script runs on Node's built-in type stripping, is type-checked by the root `astro check`, and there is still no `scripts/package.json`.

- [Docs]: `docs/before/README.md` now records the environment (WordPress 7.1.3, Astra 4.14.0, Elementor 4.3.3, CF7 6.1.7, Yoast 28.6, Starter Templates 4.7.8, PHP 8.2.29, nginx 1.26.1, MySQL 8.4.0, HTTP/1.1 with gzip only), the manual measuring checklist and how the login is kept out. Not verified: no protocol Lighthouse run exists yet, so the import has only seen the two home reports, which contain no login, and the real-login scrub of Lighthouse JSON has only been exercised with a fake login. The Chromium version was read from the Brave binary, not `brave://version`. The export-freshness check covers published content only.

## 2026-08-07

- [Feat]: landing toolkit added — `Section.astro` (container, vertical rhythm, eyebrow/title/subtitle header) plus `Header`, `Hero`, `Logos`, `Features`, `Testimonials`, `FAQ`, `CTA`, `Footer` in `src/components/sections/`. Every block takes its copy as props and ships zero JavaScript: the FAQ accordion and the mobile menu are both `<details>`/`<summary>` with `group-open:` styling, and `Icon.astro` renders `lucide-react` server-side with no `client:` directive, emitting inline SVG. `src/pages/index.astro` is now a Layout plus six spread props, with all copy in `src/lib/content/home.ts`.

- [Fix]: `site` was commented out in the Astro config, so `@astrojs/sitemap` could not emit a sitemap and every canonical/OG URL depended on `siteConfig.url` separately. Both configs are now `.ts` (`astro.config.ts`, `astro.config.docker.ts`) and import `siteConfig`, so the URL lives in one place. `sitemap-index.xml` is generated on build again, and `src/pages/robots.txt.ts` derives the sitemap URL from the same source. `output: 'static'` is now explicit.

- [Feat]: `Layout.astro` gained Organization JSON-LD, a keywords meta tag, and it now renders `Header`/`Footer` by default (`showHeader`/`showFooter` to opt out — the 404 does, to keep its full-screen design). `ClientRouter` became conditional behind a `viewTransitions` prop: it is ~4.5 kB gzip and the only script a page ships, so a single-page landing can now ship literally zero JavaScript. Verified: `dist/index.html` links only ClientRouter + a 0.07 kB page script, and contains no `astro-island` — the 194 kB React chunk Vite emits is never referenced by a page.

- [Fix]: TypeScript and `@astrojs/check` were not installed at all, so `tsconfig.json` extending `astro/tsconfigs/strict` was unenforced and there was no way to type-check `.astro` files. Added both plus a `check` script; `astro check` reports 0 errors across 31 files.

- [Fix]: quality gates were a single `.husky/pre-commit` running `npx lint-staged` and nothing else — no type check, no commit-msg hook, no pre-push, and no CI at all. `pre-commit` now also runs `astro check`; `commit-msg` runs commitlint; `pre-push` blocks direct pushes to `main` then runs format + lint + check + build; `.github/workflows/ci.yml` runs the same set on every PR. `lint-staged` now runs Prettier on `.ts`/`.tsx` too (it only ran ESLint before, so formatting drifted).

- [Fix]: `.gitignore` ignored the whole `.claude/` directory, which would have kept any shared agent config out of the repo. Now only `.claude/settings.local.json` is ignored. Added `.prettierignore` (there was none, so `prettier --check .` walked `dist/` and `.astro/`).
